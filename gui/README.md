# Crunchyroll Downloader GUI

A desktop app for the downloader, built with [Wails v3](https://v3.wails.io), React, TypeScript, Tailwind and shadcn/ui on Base UI. It uses the same `downloader` package as the CLI.

## Development

Requirements: Go, Node.js and the Wails v3 CLI (`go install github.com/wailsapp/wails/v3/cmd/wails3@latest`).

```shell
cd gui
wails3 dev     # live-reloading app; also rebuilds when ../downloader changes
wails3 build   # bin/crdl-gui(.exe)
```

Settings, including the `etp_rt` cookie of every saved account, are stored in your user config directory in a SQLite database (`%AppData%\crunchyroll-downloader\data.db` on Windows), together with the download queue, so the queue survives a restart. A `settings.json` from an older version is imported on first launch.

TypeScript bindings in `frontend/bindings` are regenerated by `wails3 dev` and `wails3 build` (or `wails3 generate bindings -ts -i`). Add UI components with `npx shadcn@latest add <name>` from `frontend/`.

## Accounts

Settings, Accounts holds any number of Crunchyroll accounts, each a name and an `etp_rt` cookie. The active account, chosen there or from the switcher in the sidebar, is used for browsing and for every episode you queue. Each queued episode remembers its account, and the queue signs in as that account before downloading it, so one queue can mix accounts (for example, to spread episodes over several accounts' stream and rate limits). Right-click a queued episode and pick **Download as** to change its account. A cookie saved by an older version becomes an account named "Main".

### Account mixer

Turn on **Settings, Rate limits, Account mixer** (it needs at least two accounts with a cookie) to spread the queue over your accounts. Each episode goes to the account that has rested longest, and the **pause between episodes** becomes a per-account rest, so with three accounts and a 3 minute pause an episode can still start every minute. When Crunchyroll rate-limits an account anyway (or it has too many open streams), the episode isn't held up: that account is benched for a cooldown (1 minute, doubling on repeated hits up to 30 minutes, and never shorter than the pause) and the episode moves straight on to the next rested account. If every account is resting, the queue shows when the next one is free. Episodes pinned to an account with **Download as** wait for that account. The queue page shows each account's state while the mixer is on. Rests and cooldowns are saved in the database, so a restart doesn't put a benched account straight back to work.
